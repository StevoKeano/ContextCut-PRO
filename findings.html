1. Application Overview

ContextCut is a local RAG (Retrieval-Augmented Generation) chat system available in two editions: Free and PRO. It lets users chat with local LLMs while automatically enriching prompts with context from a local knowledge base of markdown/text files. The PRO edition is a commercial product ($99.88 one-time) with a machine-locked license server at api.contextcut-pro.com.

Single-file, zero-dependency RAG chat. In-memory FAISS vectors, SQLite sessions, pure-Ollama embeddings. No Qdrant, no Docker, no license.

3. Free Edition (cc-free.py)

cc-free.py902 lines

Architecture

  • HTTP Server: http.server.ThreadingHTTPServer on localhost:18988
  • Vector Store: Pure-Python in-memory list + brute-force cosine similarity (FAISS optional)
  • Persistence: JSON files (vectors.json, metadata.json)
  • Sessions: SQLite with WAL journal mode
  • Embedding: Ollama /api/embed (default model: nomic-embed-text)
  • Chat: Ollama /api/chat with streaming SSE
  • Web Search: DuckDuckGo (HTML scrape fallback when duckduckgo_search not installed)
  • Frontend: Embedded single-page HTML dashboard (dark/light theme)

Limits

  • 50 files maximum in knowledge base
  • 10MB max file size
  • 32768 context window (configurable)
  • Allowed extensions: .md .txt .py .js .ts .html .css .csv .json .xml .yaml .yml .go .rs .rb .java .c .cpp .h .sh .sql .log

Key Implementation Details

  • Chunking: Text split at 1500 chars with 150-char overlap, prefers newline boundaries
  • Context injection: Web results + KB results prepended as system context before user message

4. PRO Edition (qdrant_proxy_final.py)

qdrant_proxy_final.py4854 lines

Two-Server Architecture

Client ──► Dashboard (port 18787) ──► Proxy (port 18788) ──► Upstream LLM
                                          │
                                          ├── Qdrant (context injection)
                                          ├── SQLite (sessions)
                                          └── .env sync / credential manager

Reverse Proxy Flow

  1. Client sends /v1/chat/completions to dashboard port 18787
  2. Dashboard handler extracts last user message → queries Qdrant via qdrant_context()
  3. Injects context as system message (prepended before user message)
  4. Counts tokens before/after, logs to audit log, forwards to upstream LLM
  5. Stores user + assistant messages in SQLite session
  6. Supports streaming (chunked transfer) and non-streaming modes

Context Optimization

  • Tokens counted before/after injection using tiktoken (exact) or word-count estimate
  • Pruning: if injected context exceeds CTX_LIMIT, chunks are removed from the system message from second-to-last working backward
  • Cache: LRU response cache (100 entries, 5-min TTL)
  • Per-request audit log stored in deque (max 100 entries)

Embedding System

  • Primary: Voyage AI (voyage-3) with rate-limit backoff (22s delay between requests, exponential on 429)
  • Fallback: Ollama local embedding (nomic-embed-text, mxbai-embed-large, bge-m3, qwen3-embedding:8b)
  • Dimension mapping: 768 (nomic), 1024 (mxbai, bge-m3, voyage), 4096 (qwen3)
  • Collection recreation: Changing embed model auto-deletes Qdrant collection, recreates with correct dim, triggers re-ingest
  • Auto-install: voyageai pip package auto-installed if missing when switching to Voyage mode

License System

  • License validation via POST /v1/license/validate to license server
  • Machine fingerprinting: hostname + platform + MAC address
  • Instance secret saved to ~/.contextcut/instance_secret (chmod 600)
  • Heartbeat every 900s (15 min), grace period 3600s (1 hour)
  • Seat release on shutdown via atexit hook and SIGINT/SIGTERM handler
  • Stale seat auto-release with user confirmation on startup

Two-Layer Architecture

Layer 1 — Tool-Usage Enforcer

User query → keyword matching against tool keywords → if match & no tool called → retry with instruction

Layer 2 — Confidence Scan

Response → secondary LLM call → per-passage: HIGH/MEDIUM/LOW confidence → highlighted in UI

Session Commands

  • stop, halt, cease — Stops current response
  • continue, go on, more — Continues previous response
  • revise, rewrite, rephrase — Triggers revision prompt

History Management

  • MAX_HISTORY_MESSAGES = 50
  • MAX_HISTORY_TOKENS = 4096
  • Oldest messages trimmed first when limits exceeded

  • First 4000 chars stored as payload text

7. Credential Manager

qdrant_proxy_final.py :: CredentialManager class

Machine-Bound Encryption

  • Uses Fernet (symmetric AES) from cryptography library
  • Key derivation:
    • Linux: /etc/machine-id → SHA256
    • macOS: IOPlatformSerialNumber → SHA256
    • Other: platform.node() → SHA256
  • Stored in .contextcut_creds.enc (chmod 600)
  • If copied to another machine, the file is undecryptable

Stored Secrets

  • provider — LLM provider name
  • api_key — Cloud API key
  • custom_url — Custom provider base URL
  • ollama_url — Ollama URL override
  • embed_mode — voyage / ollama
  • voyage_key — Voyage AI API key
  • embed_model — Local embedding model name

9. Test System (run_tests.py)

run_tests.py675 lines

Features

  • Sends queries with known ground truth → validates response accuracy
  • Entrapment tests: Fabricated case law/statutes test hallucination resistance (checks refusal indicators like "does not exist", "fabricated", "no such case")
  • Tolerance levels: strict (100%), moderate (80%), lenient (60%)
  • Citation verification: Advisory checking of expected citations in responses
  • Refusal indicators: 20+ phrases checked ("does not exist", "cannot confirm", "no such statute", etc.)

Modes

  • --validate : Validate test file structure without running queries
  • --show-tests : Print all test definitions
  • --ping : Quick connectivity check
  • --entrapment-only : Run only hallucination trap tests
  • --filter : Run tests matching substring in ID

Exit Codes

  • 0 = all tests passed
  • 1 = some tests failed
  • 2 = connection error / harness failure

10. Security Observations

Strengths

  • Credentials encrypted with machine-bound Fernet key
  • Shell commands filtered for destructive patterns
  • KB file access restricted to KB_DIR path prefix (path traversal protection)
  • API keys never logged; masked in UI
  • All binary file encryption (creds) at rest
  • chmod 600 on credential file

Notable Patterns

  • Free edition has no authentication — any local network user can access the dashboard
  • PRO proxy blocks dangerous Ollama endpoints (/api/pull, /api/push, /api/delete, /api/copy, /api/create)
  • License server URL is configurable via CONTEXTCUT_LICENSE_SERVER
  • Heartbeat failures don't deactivate — network blips are tolerated
