Initial Setup

1

Install Ollama on Windows

Ollama runs on the Windows host. It listens on 192.168.137.1:11434 (the ICSA-assigned IP). Pull the models you need:

ollama pull qwen3:14b-q8_0
ollama pull initium/law_model:Q8_0
ollama pull nomic-embed-text
ollama pull qwen2.5:7b
2

Deploy proxy files to Ubuntu

From Windows cmd:

scp qdrant_proxy_final.py ingest.py cc-free.py steve@192.168.137.252:~/contextcut/
3

Configure environment on proxy

cat ~/contextcut/.env
CONTEXTCUT_UPSTREAM=http://192.168.137.1:11434
CONTEXTCUT_EMBED_MODE=ollama
CONTEXTCUT_EMBED_MODEL=nomic-embed-text

CONTEXTCUT_UPSTREAM must point to the Windows Ollama instance, not localhost on the proxy.

4

Open firewall ports

sudo ufw allow 18787/tcp
sudo ufw allow 18788/tcp

By default, ufw blocks all incoming ports except SSH. Without this, the dashboard and proxy are unreachable from Windows.

5

Start the proxy

cd ~/contextcut && ./start.sh

This launches qdrant_proxy_final.py (proxy + dashboard) and ingest.py --watch (file watcher + auto-ingest) in parallel.

6

Verify it's running

On the proxy:

ss -tlnp | grep python
# → 0.0.0.0:18787  (dashboard)
# → 0.0.0.0:18788  (proxy)

From Windows browser:

http://192.168.137.252:18787
7

Ingest knowledge files

cp ~/contextcut/starterKnowledgeFiles/*.md ~/contextcut/knowledge/
# Watcher auto-ingests. Verify:
~/contextcut/venv/bin/python ~/contextcut/ingest.py --query "test"

Deploy Workflow (after editing files)

1

Copy sandbox → user's repo (WSL)

cp /mnt/e/dev/opencode/ContextCut-PRO/{filename} /mnt/e/Dev/contextcut-pro/{filename}
2

SCP to proxy (Windows cmd)

cd E:\Dev\ContextCut-PRO
scp {filename} steve@192.168.137.252:~/contextcut/
3

Restart proxy

ssh steve@192.168.137.252 "cd ~/contextcut && ./stop.sh && sleep 1 && ./start.sh"
4

Git commit (Windows cmd)

cd E:\Dev\contextcut-pro
git add {files}
git commit -m "message"
git push

Running Tests

Run from Windows E:\Dev\ContextCut-PRO (or WSL):

# Quick connectivity check
python run_tests.py --ping

# Run all 18 tests
python run_tests.py --proxy http://192.168.137.252:18788 --model "initium/law_model:Q8_0"

# Verbose output
python run_tests.py --proxy http://192.168.137.252:18788 --model "initium/law_model:Q8_0" --verbose

# Show test details
python run_tests.py --show-tests

# Validate test facts against source knowledge files
python validate_tests.py
Note: The test runner used to connect to 127.0.0.1:18788, which failed on a two-machine setup. The /stats health check was on the dashboard port (18787), not the proxy port — now fixed to fall back to /v1/chat/completions POST.

Troubleshooting

Proxy unreachable from Windows

# Check listening
ss -tlnp | grep python

# Check firewall
sudo ufw status

# Check upstream reachability (from proxy)
curl -s http://192.168.137.1:11434/api/tags | head -5

"/stats (dashboard + proxy) UNREACHABLE"

The test runner tries http://host:18787/stats first, then falls back to http://host:18788/v1/chat/completions. If both fail, either the firewall is blocking the ports or the proxy isn't running.

"502 Connection refused" on chat completions

The proxy is running but can't reach Ollama. Verify:

# On the proxy:
curl -s http://192.168.137.1:11434/api/tags   # ← not localhost!

# Check .env has the right IP:
grep CONTEXTCUT_UPSTREAM ~/contextcut/.env
Key insight: In this setup, Ollama runs on Windows at 192.168.137.1:11434, not on the proxy. CONTEXTCUT_UPSTREAM must match. The proxy's start.sh does not set this automatically — it must be in ~/.contextcut/.env or set as a process env var.

WSL can't reach the proxy

WSL uses a separate virtual network adapter and often can't route to 192.168.x.x subnets. Either:

  • Run tests from Windows cmd (not WSL)
  • SSH tunnel: ssh -L 18788:127.0.0.1:18788 steve@192.168.137.252

File watcher missed files on bulk copy

The watcher now handles on_moved and on_any_event events (was missing — root cause of missed bulk copies). Debounce is 5s. If files are still missed:

pkill -f "ingest.py --watch"
~/contextcut/venv/bin/python ~/contextcut/ingest.py --clear
~/contextcut/venv/bin/python ~/contextcut/ingest.py --watch &

cc-free.py won't start (port in use)

lsof -ti:18988 | xargs kill -9
# Or use PID file:
kill $(cat /tmp/cc-free.pid)

pkill -f "python.*cc-free" is dangerous — it matches its own pkill command.

Constraints

  • Never git commit/push from the sandbox (opencode/ContextCut-PRO) — only from E:\Dev\contextcut-pro
  • Never touch files outside E:\dev\opencode\ContextCut-PRO without asking
  • The proxy pkill pattern kills itself — use PID file or lsof -ti | xargs kill
  • ~/contextcut/venv/bin/python is the correct Python for the proxy, not the system python3
